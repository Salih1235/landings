# Базовый шаблон лендинга

Это конструктор, с которого начинается каждый заказ. Внутри — полный
референсный лендинг (контент «ремонт квартир» служит примером-заполнителем):
секции hero, пакеты цен, калькулятор, кейсы, этапы, отзывы, FAQ, форма, футер.

## Старт нового заказа

```bash
cp -r template/ clients/<имя-клиента>/
```

Дальше по шагам:

## 1. Тема (css/style.css, блок `:root` в самом верху)

Все цвета и шрифты — CSS-переменные. Перекраска под бренд клиента = замена
значений в одном блоке:

- `--bg / --surface / --tint` — фоны
- `--ink / --ink-soft` — текст
- `--accent / --accent-dn` — акцентный цвет (кнопки, ссылки, маркеры)
- `--dark / --dark-2 / --on-dark` — тёмные секции (калькулятор, форма)
- `--font-display / --font-body / --font-mono` — шрифтовые роли; сами
  подключения Google Fonts меняются в `<head>` index.html

Палитру и шрифтовую пару подбираем по нише клиента (см.
`docs/design-resources.md`: ui-ux-pro-max + референсы из Land-book/Lapa).
Не оставлять оранжево-графитовую тему «как есть» — она принадлежит демо.

## 2. Контент (index.html)

Заменить всё содержимое на клиентское:

- `<title>`, `<meta name="description">`, favicon (буква/цвет в data-URI)
- Шапка и блок контактов: вместо ссылок «Позвонить» (`href="#lead"`)
  вписать реальный телефон клиента через `tel:` — в шаблоне цифр нет
  намеренно, чтобы демо нельзя было принять за настоящую компанию
- Футер: добавить реквизиты клиента (ИП/ООО, ИНН) — в демо их нет
- Hero: заголовок-оффер, подзаголовок, цифры-факты
- Пакеты: услуги и цены клиента (можно удалить секцию, если не подходит)
- Калькулятор: тарифы в `value=` радио-кнопок и логика в js/main.js
  (секцию можно удалить целиком, если для ниши не нужна — тогда убрать и
  соответствующий блок в JS)
- Кейсы: реальные фото клиента вместо градиентных плейсхолдеров
  (`.case__photo--N` в CSS заменить на `background-image`)
- Этапы, отзывы, FAQ, форма, футер (ИНН, политика ПД!)

## 3. Отправка заявок (js/main.js, константа TG_CONFIG вверху)

1. Клиент создаёт бота через @BotFather (или делаем за него) → `botToken`
2. Добавить бота в чат/группу клиента, узнать `chatId`
3. Вписать оба значения в TG_CONFIG — форма начнёт слать заявки в Telegram
4. Пока значения пустые, форма работает в демо-режиме (успех без отправки)

## 4. Обязательно перед сдачей

- Политика обработки персональных данных — реальная страница (152-ФЗ),
  ссылка из формы и футера
- Яндекс.Метрика (счётчик клиента) перед `</head>`
- Чек-лист сдачи: docs/launch-checklist.md (появится в этапе 2)
- Анти-«яичный» чек-лист: docs/design-resources.md, раздел 4

## Устройство кода

- `index.html` — одна страница, секции независимы: любую можно удалить,
  не ломая остальные
- `css/style.css` — тема (`:root`) → база → секции по порядку → адаптив
  внизу (брейкпоинты 960px и 720px)
- `js/main.js` — TG_CONFIG, меню, reveal-анимации (уважают
  prefers-reduced-motion), калькулятор, форма с валидацией
- Зависимостей нет, сборки нет: папка кладётся на любой хостинг как есть
